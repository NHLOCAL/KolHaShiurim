מערכת זו, פרי הפיתוח של **זה קל מערכות**, מציעה פתרון חכם, מאובטח ואוטומטי לניהול והעלאת שיעורי תורה למאגרי תוכן מרכזיים, כדוגמת מערכות **"קול הלשון"** בישיבות ובמוסדות תורניים.

### הרקע והבעיה

במוסדות תורניים רבים, ובפרט בישיבות, קיימות עמדות "קול הלשון" המשמשות כקיוסק לטובת ציבור הלומדים. עמדות אלו מאפשרות **הורדה** של שיעורים למכשירים ניידים, אך הן מאובטחות ואינן מאפשרות גישה למערכת הקבצים או העלאת תכנים חדשים.

במקביל, מדי יום מוקלטים בישיבה שיעורים, שיחות וועדים חדשים על ידי הבחורים עצמם באמצעות מכשירי הקלטה אישיים. במצב הקיים, התהליך לעדכון המאגר המרכזי הוא מסורבל: מנהל המערכת נדרש לאסוף פיזית את מכשירי ההקלטה מהבחורים, לאתר את הקבצים הרלוונטיים, ולהעתיק אותם באופן ידני למערכת 'קול הלשון'. זוהי משימה יומיומית שגוזלת זמן יקר, יוצרת טרחה ומהווה צוואר בקבוק.

### הפתרון: אוטומציה, אבטחה ונוחות

מערכת **קול השיעורים** נולדה כדי לפתור בדיוק את הבעיה הזו. היא מאפשרת למנהל המערכת להגדיר מראש הרשאות מדויקות לכל משתמש (בחור) והתקן ההקלטה שלו. בכך, יכול הבחור לגשת באופן עצמאי לעמדה, לחבר את מכשירו, ובאמצעות ממשק ייעודי ומאובטח – להעביר את השיעור שהקליט ישירות למערכת. כל זאת, מבלי לקבל גישה ישירה למחשב, ותוך הבטחה שהקובץ יגיע למקום הנכון, בשם הנכון ובפורמט הנכון.

## 🎯 המטרה המרכזית

- **אבטחה:** מניעת גישה לא מורשית לקבצים ותיקיות במערכת המרכזית. המשתמש פועל בתוך סביבה מבוקרת בלבד.
- **סדר וארגון:** הבטחה שכל שיעור מועתק לתיקיית הרב הנכונה, עם שם קובץ אחיד הכולל תאריך עברי, נושא ומספור אוטומטי.
- **פשטות ונוחות:** מתן ממשק משתמש אינטואיטיבי למשתמש הקצה, המופיע אוטומטית רק כאשר התקן מאושר מחובר, ומאפשר לו להעביר שיעורים באופן עצמאי וללא צורך במנהל.
- **יעילות וחיסכון בזמן:** פישוט דרמטי של תהליך עדכון המאגר, המבטל את הצורך של מנהל המערכת באיסוף והעתקה ידנית של קבצים.
- **גמישות ניהולית:** מתן כלי ניהול מרכזי למנהל המערכת להגדרת משתמשים, התקנים, רבנים והרשאות גישה בצורה גמישה ומלאה.

## ✨ תכונות עיקריות

### למנהל המערכת (Admin Panel)

*   **ניהול משתמשים:** יצירה, עריכה ומחיקה של משתמשים במערכת.
*   **ניהול התקנים:**
    *   שיוך התקנים ניידים (Disk-On-Key, נגנים וכו') למשתמשים ספציפיים על בסיס המספר הסריאלי הייחודי של ההתקן.
    *   **שינוי מספר סריאלי (אופציונלי):** אפשר להפעיל מהמערכת כלי `VolumeID` שהמנהל מוריד בנפרד מ-Microsoft. הכלי אינו כלול בפרויקט או בהתקנה.
    *   הגדרת תיקיית מקור ספציפית בהתקן (לדוגמה `records`) שממנה בלבד ניתן לקרוא קבצים.
*   **ניהול רבנים והרשאות:**
    *   הגדרת רבנים ותיקיות היעד הראשיות שלהם במחשב המרכזי.
    *   מתן הרשאות למשתמשים, המגדירות לאילו רבנים (ותיקיות) כל משתמש רשאי להעתיק קבצים.
    *   **הגבלת תיקיות משנה:** אפשרות להגביל משתמש לתיקיות משנה ספציפיות בתוך תיקיית הרב, לשמירה על סדר היררכי (לדוגמה: `תשפ"ד/בין הזמנים`).
*   **הגדרות מתקדמות:**
    *   **גיבוי ושחזור:** אפשרות לגבות את כל הגדרות המערכת (משתמשים, התקנים, הרשאות) לקובץ JSON, ולשחזר אותן בקלות.
    *   **המרת קבצים:** אפשרות להפעיל המרה אוטומטית של כל קובץ שמע לפורמט MP3 בעת ההעתקה, כולל שליטה על איכות ה-Bitrate.

### למשתמש הקצה (User Panel)

*   **ממשק אוטומטי:** התוכנה פועלת ברקע, וממשק המשתמש נפתח באופן אוטומטי (במצב מסך מלא) רק כאשר מזוהה חיבור של התקן המוגדר במערכת.
*   **תהליך העברה פשוט:**
    1.  **בחירת קובץ:** הצגת רשימת קבצי השמע מתיקיית המקור המוגדרת בהתקן.
    2.  **השמעת בדיקה:** אפשרות להאזין לקובץ שנבחר ישירות מהממשק לפני ההעתקה.
    3.  **בחירת רב:** בחירת הרב הרלוונטי מתוך רשימה מותאמת אישית של הרבנים המורשים לאותו משתמש.
    4.  **הזנת פרטים:** הוספת נושא לשיעור (אופציונלי) באמצעות מקלדת על המסך.
    5.  **תאריך עברי:** שדה התאריך מתמלא אוטומטית בתאריך העברי הנוכחי, עם אפשרות לעריכה קלה.
*   **אוטומציה חכמה:**
    *   **שמות קבצים אחידים:** יצירת שם קובץ סטנדרטי באופן אוטומטי, לדוגמה: `01 - כז אלול התשפד - הרב פלוני - סוגיות בבבא קמא.mp3`.
    *   **מספור עוקב:** המערכת בודקת את תיקיית היעד ומעניקה לקובץ החדש את המספר הסידורי הבא בתור.
*   **סיום מאובטח:**
    *   לאחר ההעתקה, המשתמש מקבל אפשרות למחוק את קובץ המקור מההתקן כדי למנוע כפילויות.
    *   עם ניתוק ההתקן, הממשק נסגר אוטומטית.

## ⚙️ איך זה עובד?

1.  **הגדרה ראשונית (מנהל):**
    *   מנהל המערכת מפעיל את התוכנה וניגש ל"פאנל הניהול" דרך אייקון המערכת (Tray Icon).
    *   המנהל מגדיר את המשתמשים, הרבנים ותיקיות היעד שלהם.
    *   המנהל מחבר התקן, בוחר את תיקיית המקור ומשייך אותו למשתמש ולהרשאות המתאימות. במידת הצורך אפשר לשנות מספר סריאלי באמצעות `VolumeID` שהותקן בנפרד.

2.  **שימוש שוטף (משתמש קצה):**
    *   המשתמש מחבר את התקן ההקלטה שלו למחשב.
    *   המערכת מזהה את המספר הסריאלי, מאמתת את ההרשאות, ופותחת אוטומטית את ממשק ההעברה.
    *   המשתמש בוחר את קובץ השיעור, בוחר את הרב, מוסיף נושא ומאשר את ההעתקה.
    *   הקובץ מומר (במידת הצורך), מקבל שם חדש ומסודר, ומועבר לתיקייה הנכונה.
    *   המשתמש בוחר האם למחוק את קובץ המקור ומנתק את ההתקן. הממשק נסגר.

## 🛠️ סקירה טכנית

התוכנה פותחה באמצעות:
*   **Flutter:** לפיתוח ממשק משתמש חוצה-פלטפורמות (כרגע ממוקד ב-Windows).

*   **Win32 & FFI:** לאינטגרציה עמוקה עם מערכת ההפעלה Windows לצורך זיהוי התקנים וניהול חלונות.

## התקנה ושימוש ב-Windows

נדרשים Windows 10 או 11 בגרסת x64. הורידו את קובץ ההתקנה או את קובץ ה-ZIP הנייד מתוך [Releases](https://github.com/NHLOCAL/KolHaShiurim/releases), כאשר זמינה שם גרסה. בהתקנה רגילה הפעילו את קובץ ההתקנה; בגרסה הניידת חלצו את כל תוכן ה-ZIP והפעילו `kol_hashiurim.exe` מתוך התיקייה שחולצה. יש להגדיר בממשק הניהול משתמשים, רבנים ותיקיות יעד, התקנים והרשאות לפני ההעברה הראשונה. [מדריך השימוש](docs/מדריך%20שימוש.md) מפרט את השלבים.

התוכנה פועלת מקומית ואינה דורשת הפעלת רישיון או אימות חומרה. הרשאות המשתמש וההתקן ליעדי ההעתקה עדיין נאכפות בתוך התוכנה. מסד הנתונים נשמר בתיקיית Documents של המשתמש כקובץ `kol_hashiurim.sqlite`. מומלץ לבצע גיבוי JSON דרך לשונית ההגדרות לפני מעבר מחשב או התקנה מחדש; שחזור מחליף את ההגדרות הקיימות. יומן הפעולות נשמר בקובץ `logs/app_log.txt` בתוך תיקיית התמיכה של האפליקציה. יש לבדוק נתיבי יעד והרשאות כתיבה של Windows במחשב שבו התוכנה רצה.

המרה ל-MP3 היא אפשרות נפרדת שדורשת `ffmpeg` ב-PATH. אם אין צורך בהמרה, אין צורך ב-FFmpeg. לשינוי מספר סריאלי של התקן, יש להוריד באופן עצמאי את [VolumeID מאתר Microsoft](https://learn.microsoft.com/en-us/sysinternals/downloads/volumeid), לקרוא ולקבל את תנאי הכלי בעצמכם, ולהציב את `Volumeid.exe` לצד קובץ ההפעלה או בתיקייה שנמצאת ב-PATH. הכלי אינו מופץ עם הפרויקט, ושינוי מספר סריאלי אינו נדרש לשימוש הרגיל.

## פיתוח ובניית גרסה

קוד Flutter נמצא בתיקיית `src`. לבנייה ב-Windows נדרשים Flutter 3.41.9 (Dart 3.11.5), Visual Studio עם רכיב Desktop development with C++, ולהפקת מתקין גם Inno Setup 6. מתוך `src` מריצים:

```powershell
flutter pub get --enforce-lockfile
dart run build_runner build --delete-conflicting-outputs
flutter test
flutter build windows --release
```

`src/pubspec.lock` נכלל במאגר כדי לשחזר את גרסאות התלויות. תהליך GitHub Actions בונה מתקין Windows וקובץ ZIP נייד, מריץ את הבדיקות, ומעלה ארטיפקטים בענפי `main` ו-`dev`. תג גרסה תואם ל-`src/pubspec.yaml` או הפעלה ידנית יוצרים טיוטת Release לבדיקה לפני פרסום. הפעלת התהליך או יצירת תג אינה פרסום אוטומטי של הטיוטה.

לבניית מתקין ידנית משורש המאגר, לאחר `flutter build windows --release`, מריצים את Inno Setup 6:

```powershell
& "${env:ProgramFiles(x86)}\Inno Setup 6\ISCC.exe" installer\installer.iss /DMyAppVersion=0.3.0 "/DMyAppOutputDir=$PWD"
```

יישום ה-Windows הבנוי נמצא ב-`src/build/windows/x64/runner/Release`; יש לשמור את כל תוכן התיקייה ביחד כשמכינים חבילה ניידת. המתקין הידני נוצר בשורש המאגר בשם `KolHaShiurimSetup.exe`.

לבניית ארטיפקטים ב-GitHub לפני יצירת תג, פתחו **Actions > Build and draft Windows release > Run workflow** ובחרו בענף `dev`. האפשרות להרצה ידנית בממשק GitHub זמינה לאחר שקובץ ה-workflow יימצא בענף ברירת המחדל `main`. אחרי בדיקת הקוד והארטיפקטים אפשר ליצור תג התואם לגרסה ב-`src/pubspec.yaml` ולהעלות אותו:

```powershell
git tag v0.3.0
git push origin v0.3.0
```

התג צריך להצביע לקומיט הגרסה שנבדק; אין להזיז תג שפורסם כדי להחליף קוד. הרצת התהליך דרך תג יוצרת טיוטת Release לבדיקה ופרסום ידני. הפקודות כאן הן הוראות בלבד, ולא בוצעה העלאה או יצירת תג במסגרת עדכון התיעוד.
